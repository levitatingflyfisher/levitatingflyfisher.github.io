This directory holds the fallback fonts Flutter's web engine fetches, on
demand, when the text on screen has a character the app's own bundled fonts
(ohStyle's Lora and Nunito) do not draw: Latin Extended letters, box drawing,
symbols, other scripts, CJK, emoji. Every OpenHearth PWA is served from this
origin (levitatingflyfisher.github.io/<App>/) and points its
web/flutter_bootstrap.js fontFallbackBaseUrl at /fonts/flutter-fallback/, so
the browser asks this site for them instead of fonts.gstatic.com, and one
copy here serves the whole fleet. Nothing here is downloaded unless a
missing glyph is drawn.

724 files, 21,739,792 bytes, all WOFF2 exactly as Google Fonts serves them
(unmodified), mirrored at the paths the engine asks for: the list is
compiled into each build's main.dart.js as A.w("<name>","<path>") entries
(Flutter 3.38.7). Recipe, from any app's fresh build:

  grep -oE 'A\.w\("[^"]+","[a-z0-9]+/v[0-9]+/[^"]+\.woff2"\)' build/web/main.dart.js |
    sed -E 's/.*","(.*)"\)/\1/' | sort -u > paths.txt
  while read p; do mkdir -p "$(dirname "$p")"
    curl -sf -o "$p" "https://fonts.gstatic.com/s/$p"; done < paths.txt

A Flutter upgrade can change the list (new font versions mean new paths).
Re-run the recipe after upgrading Flutter, before deploying any PWA built
with it, and remove paths the new list no longer names.

The engine's default font, roboto/v32/..., is deliberately not mirrored:
the engine requests it eagerly on every load, it is Apache-2.0 rather than
OFL, and the apps draw their text from their bundled fonts. That request
404s here, harmlessly.
